## Por que este módulo existe

Até aqui você ligou LLMs, grafos e MCP. Ainda faltava o objeto de estudo da pós: um **agente de produção** que planeja, age, lembra, se observa e **para** quando a ação é perigosa. O OpsPilot (Mercadinho) é esse objeto. A Notas API (U1) treina o *método* de operar um agente de código (spec antes do diff) para você não “conversar o OpsPilot até ficar pronto”.

Cada pasta U2–U9 é o projeto **ao final** da unidade — não um capítulo isolado. Não misture `src/` da U3 com `web/` da U8.

```text
U1  Notas API + SDD          (você opera o agente de código)
U2  ReAct / Plan / Reflect   (como ele pensa)
U3  Tools + MCP              (como ele age)
U4  Memória + refletor       (como ele lembra e aprende)
U5  Orçamento de contexto    (como não estourar tokens)
U6  Grafo de produção        (como roteia e faz fallback)
U7  HITL + /stats            (como você ainda manda)
U8  War room                 (como o humano vê o raciocínio)
U9  Time (supervisor)        (como vários papéis se coordenam)
```

## Como estudar este capítulo

- Uma pasta por sessão. Comandos padrão (U2–U9): `npm ci`, `cp .env.example .env`, `npm run dev`, `npm test`, `npm run typecheck`.
- U2–U5: se faltar `.env.example`, copie o de [`06-langgraph-e-workflows-complexos/`](../../modulo04-criacao-de-agentes-autonomos-novo/06-langgraph-e-workflows-complexos/).
- `UNIDADE.md` lista o que o roteiro planejou e **não** entrou no snapshot — não cobre isso na demo.
- Modelos `:free` no OpenRouter: README do módulo.

## Objetivos de aprendizagem

1. Operar um agente de código com SDD (spec → plano → tarefas → implementação) e guardrails de terminal.
2. Comparar **ReAct**, **Plan-and-Execute** e **Reflection** com arena/bench (métrica no store).
3. Expor tools reais (SQLite, status de provider) e o próprio OpsPilot como **servidor MCP**.
4. Persistir conversa + memória semântica e mostrar o refletor no trace.
5. Medir tokens, sumarizar histórico e montar prompt com **orçamento por seção**.
6. Rodar o grafo de produção com roteador e fallback de modelo.
7. Ligar **HITL** (HTTP 202 + `approvalId`) e consultar `/stats` sem vazar conteúdo de PII nos logs.
8. Publicar a war room (API + `web/`) e demonstrar modo **team** (supervisor, blackboard, handoff).

## Conceitos que você precisa internalizar

| Padrão | Loop | Quando usar (intuição) |
| --- | --- | --- |
| **ReAct** | Pensar → agir → observar → repetir | Incidente com ferramenta no meio |
| **Plan-and-Execute** | Plano inteiro, depois passos | Tarefa decomponível, menos interrupção |
| **Reflection** | Produz e depois critica | Qualidade da resposta importa mais que velocidade |
| **SDD** | Spec → plano → tarefas → código | Agente de código sem “vai escrevendo” |
| **HITL** | Agente propõe; humano libera | Ação irreversível ou cara (M08 P2) |
| **Blackboard** | Estado compartilhado entre papéis | U9: análise + plano + ação |

Paper ReAct: Yao et al., [arxiv 2210.03629](https://arxiv.org/abs/2210.03629) (já no README raiz / M08).

## Roteiro de aulas

### U1 — Arquitetura de agentes de código (~4 h)

**A ideia.** O produto não é a API de notas: é o **fluxo** `/especificar` → `/planejar` → `/tarefas` → `/implementar`. Você adiciona uma feature **sem** abrir `src/` primeiro. Guardrail de terminal existe porque agente de código com shell irrestrito é o incidente Replit em escala de sala.

[`01-arquitetura-de-agentes-de-codigo/`](../../modulo04-criacao-de-agentes-autonomos-novo/01-arquitetura-de-agentes-de-codigo/) — [`UNIDADE.md`](../../modulo04-criacao-de-agentes-autonomos-novo/01-arquitetura-de-agentes-de-codigo/UNIDADE.md)  
Projeto: [`notas-api/`](../../modulo04-criacao-de-agentes-autonomos-novo/01-arquitetura-de-agentes-de-codigo/notas-api/). Specs em `specs/`.

Live SDD: [`lives/2026-05-27/`](../../lives/2026-05-27/).

### U2 — Padrões de raciocínio (~4 h)

**A ideia.** Três estratégias, a mesma arena, **número** no store. Sem métrica, “ReAct é melhor” é palpite. OpsPilot nasce aqui (Mercadinho).

[`02-padroes-de-raciocinio-e-execucao/`](../../modulo04-criacao-de-agentes-autonomos-novo/02-padroes-de-raciocinio-e-execucao/)  
Specs 001–002. `npm run arena -- --strategies react,plan-execute` e `npm run bench`.  
`src/strategies/{react,plan-execute,reflect}.ts`.

**Entrega C04.2.** Tabela com acertos das estratégias que você rodou — não um parágrafo de opinião.

### U3 — Function calling e tools (~4 h)

**A ideia.** Pensar sem tool é redação. Tool tem **schema JSON**; o modelo escolhe nome + argumentos; o runtime executa. SQLite é o mundo real do Mercadinho. `npm run mcp` expõe o OpsPilot como servidor — o M03 deixa de ser exercício isolado.

[`03-function-calling-e-tool-use/`](../../modulo04-criacao-de-agentes-autonomos-novo/03-function-calling-e-tool-use/)  
Specs 003–006 (+ 007 já no commit). `POST /chat`.

**O que observar no trace.** Qual tool foi escolhida, com quais args, e se o schema impediu um argumento inválido.

### U4 — Memória e reflexão (~4 h)

**A ideia.** Histórico linear ≠ memória semântica. A primeira é a fita da conversa; a segunda é recall por embeddings (`POST /memories`). O evento `learning` é o refletor visível: o agente anota o que errou.

[`04-memoria-e-reflexao-em-agentes-autonomos/`](../../modulo04-criacao-de-agentes-autonomos-novo/04-memoria-e-reflexao-em-agentes-autonomos/)  
007–009. `/chat` com `conversationId`/`userId`.

A 1ª run baixa embeddings Hugging Face — não é freeze.

### U5 — Contextos (~4 h)

**A ideia.** Contexto é orçamento. `ContextBuilder` monta o prompt **por seção** (sistema, memórias, resumo, turno). `conversa-longa.sh` (30 turnos) força o evento `summarize`. Sem isso, o grafo da U6 estoura ou fica caro em silêncio.

[`05-gerenciamento-de-contextos/`](../../modulo04-criacao-de-agentes-autonomos-novo/05-gerenciamento-de-contextos/)  
010–012.

### U6 — LangGraph de produção (~4 h)

**A ideia.** A partir daqui `/chat` **sem** `strategy` é feature, não bug: o grafo **roteia** (`route` / `routeReason`) e faz fallback de modelo. É o 2.1 (gateway) + 2.2 (grafo) aplicados a um produto.

[`06-langgraph-e-workflows-complexos/`](../../modulo04-criacao-de-agentes-autonomos-novo/06-langgraph-e-workflows-complexos/)  
013–014. Sem `web/` ainda. U6 e U7 podem agrupar commits — leia o `UNIDADE.md`.

### U7 — Observabilidade e autonomia (~4 h)

**A ideia.** Autonomia sem freio não é madura: é não ter product owner. `awaitHumanApproval: true` → **HTTP 202** + `approvalId`. `/stats` agrega sem despejar PII no log. Este é o Approval Gate que o M08 vai desenhar em canvas.

[`07-observabilidade-e-limites-de-autonomia/`](../../modulo04-criacao-de-agentes-autonomos-novo/07-observabilidade-e-limites-de-autonomia/)  
015. `GET /requests/:id`; `GET /stats`.

### U8 — War room publicado (~4 h)

**A ideia.** Trace invisível não governa. API `:3000` + `web/` `:5173` (Vite). README da pasta com Pages. O humano vê o raciocínio; o checkpoint é um pedido que aparece como aprovação pendente.

[`08-projeto-pratico-opspilot-publicado/`](../../modulo04-criacao-de-agentes-autonomos-novo/08-projeto-pratico-opspilot-publicado/)  
016–017. `.github/workflows/deploy.yml`.

### U9 — Multiagente (~4 h)

**A ideia.** Um único ReAct não dá conta de “analisa + planeja + age” em paralelo responsável. Supervisor despacha; blackboard compartilha estado; `handoff` é evento, não metáfora. Pedidos que exigem os três papéis → rota `team`.

[`09-multi-agent-systems/`](../../modulo04-criacao-de-agentes-autonomos-novo/09-multi-agent-systems/)  
018 `src/team/`.

O M08 M3 amplia isso para seis padrões; aqui você *vê* um.

## Atividades práticas

1. U1: uma feature nova na Notas API só via spec (não edite `src/` na mão primeiro).
2. U2: tabela arena ReAct vs Plan-and-Execute (acertos).
3. U3: uma tool sua (mesmo stub) registrada e chamada no trace.
4. U5 **ou** U7: evidência de sumarização **ou** aprovação humana.
5. U8 ou U9: print da war room (raciocínio visível ou handoff).

## Erros comuns

- `git checkout` “para ver a U5” dentro da pasta da U8. Cada pasta já é o fim da unidade.
- Demo da war room sem nunca ter forçado 202. Sem HITL, é um chat bonito.
- Ignorar o `UNIDADE.md` e cobrar `graph:draw` ou budget em USD que **não** entrou no snapshot.
- Logs com payload de conversa. `/stats` existe para você não fazer isso.
