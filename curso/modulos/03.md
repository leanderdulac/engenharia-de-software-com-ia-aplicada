## Por que este módulo existe

No M01 você *usou* um MCP pronto (Playwright, Grafana). Aqui você **escreve** o servidor, **embrulha** uma API legado e **nega** acesso sem identidade de máquina. Sem isso, “agente com tools” no M04 é magia: você não sabe quem autentica, nem a diferença entre o processo do Cursor e o processo que fala com o Mongo.

A metáfora da live é a certa: MCP é o **USB-C da IA**. O problema que ele resolve é o N×M (cada modelo × cada ferramenta = integração artesanal). Theory: [`lives/2026-02-24/base-teorica/mcp-model-context-protocol.md`](../../lives/2026-02-24/base-teorica/mcp-model-context-protocol.md).

```text
Usuário
  → Host (Cursor, VS Code, Claude Desktop)
      → Client MCP (dentro do host)
          → Server MCP (seu processo: tools / resources / prompts)
              → sistema real (FS, Mongo, Fastify, CSV)
```

## Como estudar este capítulo

1. Distinga **host**, **client** e **server** em voz alta antes do lab 05. Se misturar os três, o Inspector não faz sentido.
2. Suba a API legado **antes** do MCP nos labs 06–09.
3. READMEs de `customers-mcp` que falam CipherSuite/AES estão copiados — o código de customers é CRUD.

## Objetivos de aprendizagem

1. Ligar um agente LangGraph a **várias** tools MCP (FS, Mongo, CSV) e responder sobre `data/sales.csv`.
2. Expor um servidor MCP **do zero** (resources, prompts, tools) e abri-lo no Inspector.
3. Embrulhar uma **API legado** Fastify+Mongo como MCP (CRUD).
4. Colocar **JWT, RBAC e service token** na API e recusar o MCP sem token.
5. (Desafio) Publicar o pacote MCP num registry **privado** Verdaccio **ou** consumir MCP via LangChain `MultiServerMCPClient`.

## Conceitos que você precisa internalizar

| Peça | O que é | O que não é |
| --- | --- | --- |
| **Host** | App onde o modelo e o usuário estão | O Mongo, a API Fastify |
| **Client MCP** | Conector *dentro* do host | Um `curl` avulso |
| **Server MCP** | Processo que declara `tools/list` e executa `tools/call` | O LLM |
| **Tool** | Ação (criar customer, ler CSV) | Dado passivo |
| **Resource** | Dado de leitura (schema, arquivo) | Função |
| **Prompt MCP** | Template versionado no servidor | System prompt do ChatGPT na UI |
| **Inspector** | UI de debug (`mcp:inspect`) | Produção |
| **SERVICE_TOKEN** | Identidade de *serviço* (máquina) | Senha do usuário humano |
| **Skill** | Conhecimento processual (“como fazer”) | Braço que toca o sistema (isso é MCP) |

JSON-RPC 2.0 por baixo (`stdio` local ou HTTP/SSE). Você não precisa implementar o framing na mão nos labs — o SDK faz — mas precisa saber que **não é REST improvisado**.

## Roteiro de aulas

### 3.1 — Múltiplas tools (~4 h)

**A ideia.** Um agente LangGraph que não tem tools é um chatbot. `getMCPTools()` no template devolve `[]` de propósito: sua missão é ligar FS + Mongo + CSV e responder “top produtos” com evidência no `sales.csv`.

- [`01-multiple-mcp-tools-template/`](../../modulo03-mcp-na-pratica/01-multiple-mcp-tools-template/) — `getMCPTools()` retorna `[]`
- [`01-multiple-mcp-tools-z/`](../../modulo03-mcp-na-pratica/01-multiple-mcp-tools-z/) — `fsTool`, `mongodbTool`, `reports/`

`docker-compose.yaml` (Mongo + Express). O `package.json` pode falar de SerpAPI: o código é **vendas CSV**.

**O que observar.** Quantas idas ao LLM vs quantas `tools/call`. O valor pedagógico é o *roteamento* entre tools, não a prosa da resposta.

### 3.2 — Google Trends (~2 h)

**A ideia.** Uma tool HTTP externa (SerpAPI) atrás de Fastify `/chat`. Útil se você tem chave; **opcional** se não tiver (C03.3 aceita Verdaccio ou lab 09 no lugar).

[`02-google-trends-agent/`](../../modulo03-mcp-na-pratica/02-google-trends-agent/) — único; tool `google_trends`. README errado. Scripts de teste sem pasta `tests/` visível: avalie pelo `/chat`.

**A ideia.** MCP dá braços; **instructions** (`.github/agents/*.agent.md`) dão política ao agente de código no IDE. Sem app, sem npm: copie para o seu editor e compare com o que o M04 U1 vai exigir.

### 3.5 — MCP do zero (~4 h)

**A ideia.** CipherSuite: crypto local que **ainda não** é MCP no template. No `-z` aparece `src/mcp.ts`, resources, prompts, tools e o Inspector. Este é o lab em que o README do `-z` **está correto** (AES). É o C03.1 mais limpo.

- [`05-mcps-do-zero-template/`](../../modulo03-mcp-na-pratica/05-mcps-do-zero-template/) — crypto local, **sem** MCP

**O que fazer no template.** Exponha pelo menos `list_tools` visível no Inspector. Não precisa reimplementar AES do zero se o template já cifra: o salto é o protocolo.

### 3.7 — Auth, rate limit, service token (~4 h)

**A ideia.** MCP sem autenticação é RCE com prosa educada. JWT e RBAC na API; o MCP entra com **service token** (não o JWT do usuário da UI). Sem token → 401. Este é o checkpoint que mais revela se você entendeu identidade de máquina.

- [`07-api-security-auth-rate-limiting-template/`](../../modulo03-mcp-na-pratica/07-api-security-auth-rate-limiting-template/)
- [`07-api-security-auth-rate-limiting-z/`](../../modulo03-mcp-na-pratica/07-api-security-auth-rate-limiting-z/)

Cada lado tem `nodejs-fastify-mongodb-crud-z/` e `customers-mcp-z/` (o nome `-z` **dentro** do template é armadilha). Compare a **API** template vs API da pasta `07-…-z`: JWT, `requireRole`, `/v1/auth/service-token`. MCP usa `getServiceToken.sh` e `SERVICE_TOKEN`.

**Experimento C03.2.** Uma chamada MCP sem token (falha) e com token (ok). Cole os status HTTP.

## Erros comuns

- Chamar de “MCP” qualquer `fetch` no agente. Sem `tools/list` + contrato, é só HTTP.
- Ligar o customers-mcp com a API no ar **depois** e achar que o servidor “não funciona”.
- Confundir a pasta `-z` *dentro* do template 07 com o gabarito real em `07-…-z/`.
- Publicar no npmjs. Fora de escopo; o curso usa Verdaccio.
