## Por que este módulo existe

OpsPilot, Nexus e RouteWise foram *produtos*. Aqui o objeto é o **diagrama**: Gateway → Orquestrador → Modelo+RAG → Approval Gate, com observabilidade atravessando tudo. TrialForge (documentos clínicos regulatórios) é o exemplo gravado — se você colar o PDF preenchido da Vitalis como se fosse o seu sistema, perdeu o módulo.

A decisão mais cara não é “qual LLM”. É **agente vs regra**, tarefa a tarefa, com as três perguntas do checklist — não no feeling.

```text
Cliente
  → Gateway (roteamento, cache, auth)
      → Orquestrador (grafo / padrões multiagente)
          → Modelo + RAG
          → Regras determinísticas
      → Approval Gate (humano quando o erro é caro e irreversível)
  → Observabilidade (audit-trail.jsonl, eval gate, tiering)
```

## Como estudar este capítulo

Fluxo do README: vídeo → canvas → `node` ou `python` → `audit-trail*.jsonl` → missão `Atividade N - Módulo N.pdf` **ou** checkpoint ([avaliacao.md](../avaliacao.md)); `Exemplo - Módulo N.pdf` é gabarito.

**Não copie limiares do demo** (cache, score de RAG). O canvas pede medição no seu caso.

## Objetivos de aprendizagem

1. Desenhar o diagrama **Gateway → Orquestrador → Modelo+RAG → Approval Gate** + observabilidade.
2. Decidir **agente vs regra** com o `decision-framework-tool` (não no feeling).
3. Explicar o loop ReAct e rodar o protótipo single-agent (Ollama ou pagos).
4. Escolher um dos **6 padrões** multiagente e justificar falha distribuída (CAP/Saga) no canvas.
5. Montar gateway com RAG avançado, roteamento, cache e HITL; comparar `audit-trail.jsonl`.
6. Descrever stack enterprise (tiering, eval gate, guardrail) e executar o protótipo de tiering.

## Conceitos que você precisa internalizar

### Agente vs regra (três perguntas)

Do [`decision-framework-checklist.md`](../../modulo08-arquitetura-de-sistemas-com-ia/modulo-01-fundamentos-ai-first/decision-framework-checklist.md):

1. Existe regra finita que cobre **>90% dos casos reais já observados**? → regra. Fim.
2. O erro é caro **e** a ação irreversível? → agente pode **propor**; Approval Gate síncrono.
3. O comportamento muda com o contexto de entrada? → agente com observabilidade. Senão, ainda é regra (mesmo com 40 ramos).

Casos-limite: decomponha tarefa híbrida (extração vs decisão); reversível ≠ irreversível no tipo de gate; a classificação **envelhece** (log vira regra, exceção vira agente).

### Seis padrões multiagente (M3)

Sequential, Parallel, Supervisor, Hierarchical, Group Chat, Handoff — no seletor. U9 do OpsPilot foi um Supervisor+blackboard. Aqui você **escolhe** e defende o modo de falha (CAP/Saga), não implementa os seis.

### Local vs pago

Tabela do README do módulo: Ollama é decisão de **prototipagem** (acesso, dado na máquina). Enterprise com trilha regulatória provavelmente não roda `gemma4` no laptop do analista — e isso também é arquitetura.

## Erros comuns

- Canvas com os nomes ICF/Protocolo/CSR e nenhum sistema seu. Rubrica de rastreio cai.
- Copiar números de cache/RAG do `audit-trail` como se fossem medidos no seu domínio.
- “Tudo é agente” depois da P1 ter sido SIM. O tool existe para impedir isso.
- Esquecer a tabela local vs pago no README — a entrega pede o trade-off citado.

## Ponte para o M09
