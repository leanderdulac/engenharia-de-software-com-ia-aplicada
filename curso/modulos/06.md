## Por que este módulo existe

OpsPilot era o incidente do Mercadinho no *aplicativo*. Nexus é o incidente na **plataforma**: IaC, pod em CrashLoop, CVE, conta zumbi, runbook. A tese do módulo não é “agente aplica `kubectl` sozinho”. É: **agente propõe, política audita, humano libera**. Groq + CrewAI são o motor; a nota está na governança.

Prometheus e Jaeger nos labs 4–5 são **simulados**. Trate-os como stubs de observabilidade, não como cluster de produção.

```text
Labs 1–3   fundação + IaC + K8s (o agente escreve, Checkov/OPA olham)
Labs 4–6   ReAct no incidente + preditivo + ChatOps (HITL)
Labs 7–10  Sec + CI + FinOps + RAG de runbook
Labs 11–12 guardrail dry-run + Manager hierárquico (relatório executivo)
```

## Como estudar este capítulo

Ordem **1→12**. Menu: `python3 nexus_iac_copilot.py`. Python **3.10–3.13** (não 3.14). `GROQ_API_KEY` via ambiente — o README não cria `.env`.

```bash
cd modulo06-aiops-engenharia-agentica
python3 -m venv venv
source venv/bin/activate   # Windows: venv\Scripts\activate
pip install -r requirements.txt
pip install streamlit
export GROQ_API_KEY=...
python3 nexus_iac_copilot.py
```

Dashboard opcional: `streamlit run ui/app.py` (LocalStack :4566 se for usar S3 explorer). Conceito ReAct: M04 U2 ou paper.

## Objetivos de aprendizagem

1. Subir o ambiente Python/CrewAI e disparar labs pelo menu `nexus_iac_copilot.py`.
2. Gerar IaC (Terraform) e manifesto K8s **com auditoria** de conformidade.
3. Diagnosticar incidente estilo CrashLoop com loop **ReAct** (Prometheus/Jaeger **simulados**).
4. Traduzir NL→PromQL e produzir alerta preditivo + JSON de dashboard.
5. Operar ChatOps com **HITL** (senha `GESTOR-APROVA`) e guardrail dry-run (`sim`/`nao`).
6. Triar CVE (Trivy JSON), otimizar workflow Actions, caçar zumbis FinOps, remediár via **RAG de runbook**.
7. Coordenar incidente **multidomínio** no lab 12 (Nexus Manager hierárquico) e emitir relatório executivo.

## Conceitos que você precisa internalizar

| Conceito | No Nexus |
| --- | --- |
| **IaC** | Terraform gerado *e* auditado (`check_compliance_rules`) |
| **GitOps / Canary** | Manifesto declarativo + rollout gradual (lab 3) |
| **ReAct de ops** | Thought/Action/Observation contra pod quebrado — igual U2, outro domínio |
| **ChatOps** | Ação perigosa no chat só com senha de gestor |
| **Dry-run** | Lab 11: o agente descreve o que *faria*; `nao` não aplica |
| **RAG de runbook** | Retrieval no `runbook_db.md`, não “o Llama inventa o runbook” |
| **FinOps** | Inventário com zumbis; custo é requisito, não afterthought |
| **Hierarchical crew** | Lab 12: Manager coordena SRE + Sec + FinOps |

## Erros comuns

- Python 3.14 → `ModuleNotFoundError: crewai` ou Pydantic quebrado. Use 3.10–3.13 no venv.
- Achar que o lab 5 “está incompleto” porque não há Prometheus real. É simulado.
- Entregar o lab 12 sem o 11: o ponto é o que o Manager **não** aplica sozinho.
- `kubectl` em cluster compartilhado da empresa. Só `k8s/` local.
